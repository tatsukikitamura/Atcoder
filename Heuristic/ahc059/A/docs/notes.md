# AHC059 - Stack to Match Pairs 考察ノート

## 問題の要約

- 20×20の盤面に0〜199の番号カードが2枚ずつ配置（計400枚）
- (0,0)からスタートし、スタック（山札）を持って移動
- カードを取る(Z)と山札に積まれ、上2枚が同じ番号なら消える
- カードを置く(X)で空きマスに山札上のカードを置ける
- **目標**: 全カードを消す＆**移動回数を最小化**

## 問題の特徴分析

### 制約
- N = 20 固定
- 操作上限: 16,000回
- 盤面: 400マス
- カード: 200ペア = 400枚

### スタック制約が鍵
スタック（LIFO）なので、ペアを消すには：
- **理想**: 同じ番号のカード2枚を連続で取る → 即消える
- **現実**: 途中で別のカードを取ると、それを消すまでペアが作れない

### ペアの距離分布
- 近くにあるペア → 効率よく消せる
- 遠くにあるペア → 移動コストが高い

---

## アプローチ案

### 1. 貪欲法 (Greedy) - ベースライン

**アイデア**: 現在位置から近いペアを優先的に消す

```
while カードが残っている:
    現在位置から最も近いペアを見つける
    ペアの2枚を順に訪問して取る
```

**利点**: 実装が簡単、そこそこの解が出る
**欠点**: 局所最適に陥りやすい、ルートが非効率になりがち

### 2. TSP（巡回セールスマン）的アプローチ

**アイデア**: ペアを消す順序を最適化して総移動距離を最小化

```
1. 各ペアの重心を計算
2. ペアを頂点としたグラフでTSP的な経路を求める
3. その順序でペアを消していく
```

**利点**: 全体的な移動効率が良い
**欠点**: スタック制約を無視している、最適順序が必ずしも実行可能とは限らない

### 3. スタックを活用した高度な戦略

**アイデア**: 「置く」操作を活用して、スタック制約を緩和

```
- カードを一時的に空きマスに「置く」ことで
- スタックに積まれた邪魔なカードを退避
- 後で回収して消す
```

**利点**: より柔軟なペア消去が可能
**欠点**: 空きマス管理が複雑、操作回数が増える

### 4. 焼きなまし法 (Simulated Annealing)

**アイデア**: ペアを消す順序を焼きなましで最適化

```python
状態: ペアを消す順序の列
近傍操作:
    - 2つのペアの順序をスワップ
    - 1つのペアの位置を移動
評価関数: その順序で実行した時の総移動距離
```

**利点**: 大域的な最適解に近づける
**欠点**: 評価にシミュレーションが必要で計算コストが高い

### 5. ビームサーチ

**アイデア**: 状態空間を幅優先的に探索、有望な状態のみ保持

```
状態: (現在位置, 残りカード, スタック状態)
各ステップで次の行動候補を生成
評価値の高い上位k個のみ保持
```

**利点**: スタック制約を正確に扱える
**欠点**: 状態空間が大きく、深さが限られる

---

## 推奨アプローチ

### Phase 1: 貪欲ベースライン
まず単純な貪欲法を実装してスコアを確認

### Phase 2: 改良版貪欲 + 局所探索
- ペアを消す順序を最適化
- k-opt的な改善を繰り返す

### Phase 3: 焼きなまし法
- 順序の最適化を焼きなましで行う
- 近傍操作を工夫（スワップ、挿入、2-opt等）

---

## 評価関数の設計

```
スコア = N² + 2N³ - K （全カード消去時）
       = 400 + 16000 - K
       = 16400 - K

K（移動回数）を最小化することが目標
```

理論的下界:
- 全ペアの最短距離の合計 + 連結に必要な移動
- 実際はスタック制約でこれより大きくなる

---

## 実装優先度

1. **入出力・シミュレーション基盤** ← 最優先
2. **貪欲法ベースライン**
3. **可視化対応**（デバッグ用）
4. **焼きなまし法による順序最適化**
5. **「置く」操作を活用した改良**

---

## 注意点

- 移動回数のみがスコアに影響（Z/X操作は回数制限のみ）
- 操作上限16,000回を超えないよう注意
- 全カード消去できないと大幅減点
