## 概要

あなたは、ある家電量販店の販売管理システムを作成することになった。このシステムは、家電量販店で売られている商品の情報や、商品を販売する販売員の販売実績を管理し、利益率を一定以上に保つことが主な役割である。

従来、家電量販店の販売員は商品の販売の際、個人の裁量で値引き交渉への対応を行ってきたが、このシステムでは値引き要求を承認してよいかどうかをそれまでの販売情報を元に判断し販売員に通達する仕組みとなっている。より具体的には、システムは販売後の商品と販売員の利益率を計算し、その値が一定以上となる場合のみ販売を許可する。

また店舗管理者もこのシステムを利用し、商品を登録及び削除することや、現在までの利益率実績を閲覧することができる。

上記の説明では、細かい仕様や具体的な入出力方式はまだ書かれていないことに注意せよ。下記の「詳細な仕様」に基づいて、販売管理システムの画面に表示するデータを出力するプログラムを実装せよ。

## 採点

構築すべきシステムが複雑なので、一部の種類のクエリに対応すれば正答できる「基本実装」というテストケースが用意されている。基本実装をスキップして応用実装にチャレンジすることもできるが、**まず基本実装が動作することを確認してから応用実装に着手することを強く勧める。**

基本実装のテストケースでは、後述する「商品価格変更クエリ」「販売員利益率閲覧クエリ」「商品利益率閲覧クエリ」は与えられないことが保証される。

それぞれのクエリが正しく実装されているかを確認するための秘密のテストが用意されているため、もし公開テストケースで満点が取れたとしても、最終的な結果が満点ではない可能性がある。そのため、公開テストケースで満点が取れても、プログラムにミスがないか確認することを勧める。

## 詳細な仕様

### 時刻

- 時刻は `YYYY/MM/DD-hh:mm:ss` 形式で表される。
  - `YYYY/MM/DD` は `YYYY` 年 `MM` 月 `DD` 日であることを表す文字列である。
  - `hh:mm:ss` は `hh` 時 `mm` 分 `ss` 秒であることを表す文字列であり、`00:00:00` から `23:59:59` まで（両端含む）の \\(24\\) 時間表記で与えられる。
  - 時刻を表すそれぞれの数について、与えられる桁数は固定であり、適切に \\(0\\) 埋めされて与えられる。
  - 入力で与えられる時刻は `2000/01/01-00:00:00` から `2099/12/31-23:59:59` まで（両端含む）の範囲に含まれることが保証される。
  - 与えられる時刻はグレゴリオ暦に則ったものである。
  - 閏秒は考慮しない。

### 販売員

- 商品を販売する販売員は \\(n\\) 人存在し、各販売員にはそれぞれ \\(1\\) から \\(n\\) までの **販売員 ID**が付与されている。

### 商品の登録

- 店舗管理者は、商品名、商品原価、商品定価を指定して、新たな商品を登録することができる。登録されたそれぞれの商品に対して、**商品 ID** が付与される。
  - 商品 ID は整数であり、この値によって予約が区別される。
  - 登録された時刻が早い商品から順に、\\(1, 2, 3, \ldots\\) と商品 ID が割り振られる。
    - 付与された商品 ID の先頭には、余分な \\(0\\) (leading zero) は付いていない。
  - 同じ商品名の商品を複数登録することはできない。

### 商品の販売

- 各販売員は、買い物客との交渉によって販売価格を決定し、販売に合意した場合、システムに販売要求を行う。システムは販売要求を許可する場合 **販売許可 ID** を発行し、販売員に送信する。システムが販売要求を許可しない場合、販売許可 ID は発行されない。販売許可 ID が発行された後、販売員は買い物客に商品を販売し、システムに販売の完了を登録する。
  - 許可された時刻が早い販売から順に、\\(1, 2, 3, \ldots\\) と販売許可 ID が発行され割り振られる。
  - システムが販売要求を許可する条件については後述する。
  - システムに販売が許可されなかった場合、販売員が販売の完了をシステムに登録することはできない。
  - 販売要求に対する許可は次の条件のいずれかを満たした場合失効し、許可が失効した後にその販売の完了をシステムに登録することはできない。
    - その販売の完了がシステムに登録される前に、同じ販売員から次の販売要求があったとき
    - その販売の完了がシステムに登録される前に、日付が変わったとき
    - その販売許可に対応する販売の完了がシステムに登録されたとき
  - 全ての買い物客は販売員を介してのみ商品を購入するものとする。

### 利益率

- **販売員利益率**は各販売員に対して次のように定義される数値である。
  - ある販売員が今までに販売した商品の販売価格の総和を \\(S\\)、商品原価の総和を \\(C\\) とするとき、その販売員の販売員利益率は \\(\frac{S-C}{S}\\) と定義される。
    - ただし、その時点で販売の完了がシステムに登録されている販売の履歴のみが、販売員利益率の算出に関与する。**そのような販売の履歴が存在しない場合、販売員利益率は \\(0\\) と定義する。**
- **商品利益率**は各商品に対して次のように定義される数値である。
  - ある商品が販売された履歴について販売価格の総和を取った金額を \\(S\\)、商品原価の総和を取った金額を \\(C\\) とするとき、その商品の商品利益率は \\(\frac{S-C}{S}\\) と定義される。
    - ただし、その時点で販売の完了がシステムに登録されている販売の履歴のみが、商品利益率の算出に関与する。**そのような販売の履歴が存在しない場合、商品利益率は \\(0\\) と定義する。**

### 販売要求が許可される条件

- 販売価格が商品定価と等しい場合、システムは販売員からの販売要求を許可する。
- 販売価格が商品定価より高い場合、システムは販売員からの販売要求を許可しない。
- 販売価格が商品定価未満である場合は、システムは次の条件の全てを満たすときに限り、販売員からの販売要求を許可する。
  - 販売価格が商品原価以上である。
  - 販売が即時に完了したと仮定した際に、販売完了後の該当販売員の販売員利益率が \\(\mathrm{rate}\\) 以上となる。
    - ただし、\\(\mathrm{rate}\\) はシステムの起動時に与えられる \\(0\\) 以上 \\(1\\) 未満の実数である。
  - 販売が即時に完了したと仮定した際に、販売完了後の該当商品の商品利益率が \\(\mathrm{rate}\\) 以上となる。

### 商品の削除

- 店舗管理者は、商品 ID を指定して、登録済みの商品をシステムから削除することができる。
  - ただし、該当する商品を対象とする販売要求に対する許可で有効なもの(失効していないもの)が存在する場合、削除を行うことはできない。
  - 販売員はシステムから削除された商品に対する販売要求を行うことはできない。
  - 削除後に、削除された商品と同じ商品名の商品を再度登録することは可能である。

### 期間内利益率（応用実装）

- 通常の利益率は、算出時点で販売の完了がシステムに登録されている販売の履歴全てが関与するが、ある期間内に販売が完了した販売の履歴のみを対象として算出した利益率を**期間内利益率**とする。詳細な定義を以下に示す。
  - **期間内販売員利益率**は与えられた販売員と期間の組に対して次のように定義される数値である。
    - 販売員が**期間内に**販売を完了した商品の販売価格の総和を \\(S\\)、商品原価の総和を \\(C\\) とするとき、その販売員の期間内販売員利益率は \\(\frac{S-C}{S}\\) と定義される。**そのような販売の履歴が存在しない場合、期間内販売員利益率は \\(0\\) と定義する。**
  - **期間内商品利益率**は与えられた商品と期間の組に対して次のように定義される数値である。
    - 商品が**期間内に**販売された履歴について販売価格の総和を取った金額を \\(S\\)、商品原価の総和を取った金額を \\(C\\) とするとき、その商品の期間内商品利益率は \\(\frac{S-C}{S}\\) と定義される。**そのような販売の履歴が存在しない場合、期間内商品利益率は \\(0\\) と定義する。**
  - 販売が完了した時刻が期間に含まれるかどうかによって期間内利益率に関与するかどうかが決定され、販売要求が行われた時刻は関係しないことに注意せよ。また、販売が完了した時刻が期間の始点または終点と一致する場合も期間に含まれるものとする。

### 商品価格の変更（応用実装）

- 店舗管理者は、商品 ID を指定して、登録済みの商品の商品原価及び商品定価を変更することができる。
  - ただし、該当する商品を対象とする販売要求に対する許可で有効なもの(失効していないもの)が存在する場合、変更を行うことはできない。
  - 変更後の商品価格は、変更後に販売要求が行われた販売にのみ適用され、変更前に完了していた販売の履歴における商品原価及び商品定価はその販売が完了した当時の価格を常に使用する。

### 利益率の閲覧（応用実装）

- 店舗管理者は、期間を指定して、各販売員および各商品を期間内販売員利益率・期間内商品利益率の降順に並べ替えて閲覧することができる。

## 入出力形式

- プログラムに与えられる入力は、標準入力を介して行われる。
  - 改行コードは `\n` (<LF>) である。最終行の末尾にも改行コードが付与される。
- 入力は、以下のようなフォーマットに従う。
```math
\(\mathrm{rate}\)
\(n\)
\(\mathrm{seller\_name}_1\)
\(\mathrm{seller\_name}_2\)
\(\vdots\)
\(\mathrm{seller\_name}_n\)
\(m\)
\(q_1\)
\(q_2\)
\(\vdots\)
\(q_m\)
```

- 許容する利益率の下限値 \\(\mathrm{rate}\\) が \\(1\\) 行目に与えられる。\\(\mathrm{rate}\\) は \\(0\\) 以上 \\(1\\) 未満の実数であり、小数点以下第二位まで与えられる。
- 販売員の人数 \\(n\\) が \\(2\\) 行目に与えられる。\\(n\\) は \\(1\\) 以上 \\(1{,}000\\) 以下の整数である。
- \\(3\\) 行目以降の \\(n\\) 行にわたって、各販売員の名前が与えられる。
  - \\(i+2\\) 行目 (\\(1 \le i \le n\\))に与えられるのは、販売員 ID が \\(i\\) である販売員の名前であり、英小文字および英大文字から構成される \\(1\\) 文字以上 \\(20\\) 文字以下の文字列である。
- その次の行に、クエリの個数 \\(m\\) が与えられる。\\(m\\) は \\(1\\) 以上 \\(2{,}000\\) 以下の整数である。
- それ以降の \\(m\\) 行にわたって、クエリ \\(q_i\\) が \\(1\\) 行に \\(1\\) つずつ与えられる。各クエリは「商品登録クエリ」、「販売要求クエリ」、「販売完了クエリ」、「商品削除クエリ」、「商品価格変更クエリ」、「販売員利益率閲覧クエリ」、「商品利益率閲覧クエリ」の \\(7\\) 種類のいずれかである。
- クエリは時系列順で与えられることが保証される。また、\\(2\\) 個目以降のクエリが送られる時刻は直前のクエリが与えられた時刻より \\(1\\) 秒以上遅いことが保証される。
- クエリで与えられる各種 ID の制約は以下の通りである。
  - クエリで与えられる、販売員 ID を表す整数は、\\(1\\) 以上 \\(n\\) 以下であることが保証される。
  - クエリで与えられる、商品 ID を表す整数は、\\(1\\) 以上 \\(2{,}000\\) 以下であることが保証される。
  - クエリで与えられる、販売許可 ID を表す整数は、\\(1\\) 以上 \\(2{,}000\\) 以下であることが保証される。
- 各クエリの詳細なフォーマット及び出力すべき内容は以下に示す。

### 商品登録クエリ（基本実装・応用実装）

- 入力
  ```plain
  register-item: {時刻} {商品名} {商品原価} {商品定価}
  ```
  - `register-item:`: 文字列 `register-item:`
  - `{時刻}`: クエリが送られた時刻が時刻形式で与えられる。
  - `{商品名}`: 商品の名称を表す。英小文字、英大文字および数字から構成される \\(1\\) 文字以上 \\(20\\) 文字以下の文字列である。
  - `{商品原価}`: 商品の原価を表す。\\(1\\) 以上 \\(10{,}000{,}000\\) 以下の整数で与えられる。
  - `{商品定価}`: 商品の定価を表す。\\(1\\) 以上 \\(10{,}000{,}000\\) 以下の整数で与えられる。
  - 各要素は \\(1\\) つの半角スペースで区切られている。

- 出力
  以下の条件を上から順に確認し、最初に当てはまった条件に対応する処理を実行せよ。
  - 現時点でシステムに登録されており削除されていない商品の中に、クエリで指定された商品名と名称が完全に一致する商品が存在する場合、登録を行わない。また、以下のエラーを出力する。
    ```plain
    register-item: duplicated item
    ```
  - この商品を定価で販売した場合の利益率、つまり \\(\frac{\mathrm{商品定価}-\mathrm{商品原価}}{\mathrm{商品定価}}\\) が \\(\mathrm{rate}\\) 未満である場合、登録を行わない。また、以下のエラーを出力する。
    ```plain
    register-item: too cheap price
    ```
  - そうでない場合、商品を登録し、以下を出力する。
    ```plain
    register-item: {商品 ID}
    ```
    - `{商品 ID}`: 登録された商品の商品 ID を表す整数。

### 販売要求クエリ（基本実装・応用実装）

- 入力
  ```plain
  request-sale: {時刻} {販売員 ID} {商品 ID} {販売価格}
  ```
  - `request-sale:`: 文字列 `request-sale:`
  - `{時刻}`: クエリが送られた時刻が時刻形式で与えられる。
  - `{販売員 ID}`: 販売要求を行った販売員の販売員 ID を表す整数が与えられる。
  - `{商品 ID}`: 販売要求を行う対象の商品の商品 ID を表す整数が与えられる。
  - `{販売価格}`: 販売員が要求した販売価格。\\(1\\) 以上 \\(10{,}000{,}000\\) 以下の整数で与えられる。
  - 各要素は \\(1\\) つの半角スペースで区切られている。

- 出力
  以下の条件を上から順に確認し、最初に当てはまった条件に対応する処理を実行せよ。
  - クエリで指定された商品 ID に対応する商品が登録されていない、もしくはクエリが送信された時点で既に削除されている場合は、販売を許可しない。また、以下のエラーを出力する。
    ```plain
    request-sale: no such item
    ```
  - クエリで指定された販売価格が指定された商品の定価より高額な場合は、販売を許可しない。また、以下のエラーを出力する。
    ```plain
    request-sale: too expensive price
    ```
  - 上の場合以外で、先述した「販売要求が許可される条件」を満たさない場合は、販売を許可しない。また、以下のエラーを出力する。
    ```plain
    request-sale: too cheap price
    ```
  - そうでない場合、販売を許可し、以下を出力する。
    ```plain
    request-sale: {販売許可 ID}
    ```
    - `{販売許可 ID}`: 許可された販売の販売許可 ID を表す整数。

### 販売完了クエリ（基本実装・応用実装）

- 入力
  ```plain
  complete-sale: {時刻} {販売員 ID} {販売許可 ID}
  ```
  - `complete-sale:`: 文字列 `complete-sale:`
  - `{時刻}`: クエリが送られた時刻が時刻形式で与えられる。
  - `{販売員 ID}`: システムにクエリを送信した販売員の販売員 ID を表す整数が与えられる。
  - `{販売許可 ID}`: 対象の販売許可の販売許可 ID を表す整数が与えられる。
  - 各要素は \\(1\\) つの半角スペースで区切られている。

- 出力
  以下の条件を上から順に確認し、最初に当てはまった条件に対応する処理を実行せよ。
  - クエリで指定された販売許可 ID に対応する販売が存在しない場合、販売の完了の登録を行わない。また、以下のエラーを出力する。
    ```plain
    complete-sale: no such sale
    ```
  - クエリで指定された販売許可 ID に対応する販売要求を行った販売員が、クエリで指定された販売員 ID に対応する販売員と異なる場合、販売の完了の登録を行わない。また、以下のエラーを出力する。
    ```plain
    complete-sale: unauthorized operation
    ```
  - クエリで指定された販売許可 ID に対応する販売許可が既に失効している場合、販売の完了の登録を行わない。また、以下のエラーを出力する。
    ```plain
    complete-sale: permission expired
    ```
  - そうでない場合、販売の完了を登録し、以下を出力する。
    ```plain
    complete-sale: ok
    ```

### 商品削除クエリ（基本実装・応用実装）

- 入力
  ```plain
  delete-item: {時刻} {商品 ID}
  ```
  - `delete-item:`: 文字列 `delete-item:`
  - `{時刻}`: クエリが送られた時刻が時刻形式で与えられる。
  - `{商品 ID}`: 削除する商品の商品 ID を表す整数が与えられる。
  - 各要素は \\(1\\) つの半角スペースで区切られている。

- 出力
  以下の条件を上から順に確認し、最初に当てはまった条件に対応する処理を実行せよ。
  - クエリで指定された商品 ID に対応する商品が登録されていない、もしくはクエリが送信された時点で既に削除されている場合は、商品の削除を行わない。また、以下のエラーを出力する。
    ```plain
    delete-item: no such item
    ```
  - クエリで指定された商品 ID に対応する商品を対象とするような販売許可で有効なもの(失効していないもの)が存在する場合、商品の削除を行わない。また、以下のエラーを出力する。
    ```plain
    delete-item: sales in progress
    ```
  - そうでない場合、商品の削除を行い、以下を出力する。
    ```plain
    delete-item: ok
    ```

### 商品価格変更クエリ（応用実装）

- 入力
  ```plain
  update-item: {時刻} {商品 ID} {商品原価} {商品定価}
  ```
  - `update-item:`: 文字列 `update-item:`
  - `{時刻}`: クエリが送られた時刻が時刻形式で与えられる。
  - `{商品 ID}`: 価格を変更する商品の商品 ID を表す整数が与えられる。
  - `{商品原価}`: 変更後の原価を表す。\\(1\\) 以上 \\(10{,}000{,}000\\) 以下の整数で与えられる。
  - `{商品定価}`: 変更後の定価を表す。\\(1\\) 以上 \\(10{,}000{,}000\\) 以下の整数で与えられる。
  - 各要素は \\(1\\) つの半角スペースで区切られている。

- 出力
  以下の条件を上から順に確認し、最初に当てはまった条件に対応する処理を実行せよ。
  - クエリで指定された商品 ID に対応する商品が登録されていない、もしくはクエリが送信された時点で既に削除されている場合は、商品価格の変更を行わない。また、以下のエラーを出力する。
    ```plain
    update-item: no such item
    ```
  - クエリで指定された商品 ID に対応する商品を対象とするような販売許可で有効なもの(失効していないもの)が存在する場合、商品価格の変更を行わない。また、以下のエラーを出力する。
    ```plain
    update-item: sales in progress
    ```  
  - 商品価格の変更後にこの商品を定価で販売した場合の利益率、つまり \\(\frac{\mathrm{商品定価}-\mathrm{商品原価}}{\mathrm{商品定価}}\\) が \\(\mathrm{rate}\\) 未満となる場合、商品価格の変更を行わない。また、以下のエラーを出力する。
    ```plain
    update-item: too cheap price
    ```
  - そうでない場合、商品価格の変更を行い、以下を出力する。
    ```plain
    update-item: ok
    ```

### 販売員利益率閲覧クエリ（応用実装）

- 入力
  ```plain
  get-margin-sellers: {時刻} {期間始点} {期間終点}
  ```
  - `get-margin-sellers:`: 文字列 `get-margin-sellers:`
  - `{時刻}`: クエリが送られた時刻が時刻形式で与えられる。
  - `{期間始点}`: 期間内利益率を計算する期間の始点にあたる時刻が時刻形式で与えられる。
  - `{期間終点}`: 期間内利益率を計算する期間の終点にあたる時刻が時刻形式で与えられる。
  - 各要素は \\(1\\) つの半角スペースで区切られている。

- 出力
  以下の条件を上から順に確認し、最初に当てはまった条件に対応する処理を実行せよ。
  - クエリで指定された期間始点が期間終点より後の時刻である場合は、期間内販売員利益率の出力を行わない。また、以下のエラーを出力する。
    ```plain
    get-margin-sellers: invalid time period
    ```
  - そうでない場合、\\(n\\) 人の販売員それぞれについて、クエリが送信された時点の、クエリで指定された期間における期間内販売員利益率を求め、**期間内販売員利益率の降順**に全て出力する。
    - また、期間内販売員利益率が等しい販売員が複数存在する場合、それらは販売員 ID の昇順で出力する。
      - ここで比較する期間内販売員利益率は後述する四捨五入を行う前の数値である。
  - \\(1\\) つのテストケースに含まれるこの種類のクエリは、**\\(100\\) 回以下**であることが保証される。
  - 出力のフォーマットを以下に示す。
```math
get-margin-sellers:
\(\mathrm{id}_1\) \(\mathrm{name}_1\) \(\mathrm{margin}_1\)
\(\mathrm{id}_2\) \(\mathrm{name}_2\) \(\mathrm{margin}_2\)
\(\vdots\)
\(\mathrm{id}_n\) \(\mathrm{name}_n\) \(\mathrm{margin}_n\)
```
  - \\(2\\) 行目以降の \\(n\\) 行では、それぞれの販売員の情報を \\(1\\) 行ずつ出力する。
    - \\(\mathrm{id}_i\\) には \\(i\\) 番目の販売員の販売員 ID を整数で出力する。
    - \\(\mathrm{name}_i\\) には \\(i\\) 番目の販売員の名前を出力する。
    - \\(\mathrm{margin}_i\\) には \\(i\\) 番目の販売員の期間内販売員利益率を**小数点以下第四位で四捨五入し、小数点以下第三位まで出力する。**
